# Яндекс.Метрика — выгрузка статистики

Скрипт `metrika.mjs` тянет данные из Яндекс.Метрики через [Stat API v1](https://yandex.ru/dev/metrika/ru/stat/). Self-hosted, без сторонних зависимостей.

## Когда использовать

Пользователь просит любые данные Метрики: трафик, визиты, источники, поисковые запросы, популярные страницы, география, отказы, поведение.

## Предусловия

1. **OAuth-токен** (scope `metrika:read`) в `.env` корня проекта:
   ```
   YANDEX_METRIKA_TOKEN=y0_...
   ```
   `.env` уже в `.gitignore` — токен не попадёт в git. **Никогда не хардкодить токен в коде или коммитах.**

   Как получить токен (если нет):
   - Создать приложение на https://oauth.yandex.ru/ → тип «Для доступа к API или отладки» → право `metrika:read` → скопировать ClientID.
   - Открыть `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>` → подтвердить → токен в URL после `#access_token=`.

2. **Counter ID** — дефолт `92637429` (активный счётчик рк-тек.рф из [layouts/default.vue](../../../layouts/default.vue)). Переопределяется через `METRIKA_COUNTER_ID`.
   - ⚠️ Счётчик `92221219` в `public/metrica.html` — чужой/мёртвый, не использовать.

## Запуск

```bash
npm run metrika                                  # весь отчёт, 30 дней
npm run metrika -- --days 7                      # за 7 дней
npm run metrika -- --report sources              # только источники
node .claude/skills/yandex-metrika/metrika.mjs --report search --days 14
```

Отчёты (`--report`): `overview` | `sources` | `search` | `pages` | `geo` | `all` (дефолт).

## Что отдаёт

| report | Данные |
|---|---|
| `overview` | визиты, посетители, просмотры, % отказов, глубина, ср. время |
| `sources` | источники трафика (поиск/прямые/соцсети/реклама) |
| `search` | поисковые системы + поисковые фразы (Яндекс часто прячет фразы — за полным списком в Вебмастер) |
| `pages` | топ страниц входа с % отказов |
| `geo` | топ городов (важно: Рязань/Москва) |

## Важно: троттлинг Метрики

Stat API периодически отдаёт `400 "Query is too complicated"` даже на лёгких запросах — это **интермиттентный rate-троттлинг по частоте**, а не реальная сложность (счётчик мелкий, ~90 визитов/день). Особенно чувствительны дименшн-запросы (`sources`/`search`/`pages`/`geo`).

В скрипте уже есть защита: интервал ≥1.1с между запросами + до 8 ретраев с растущим бэкоффом. Но при бурсте окно может не успеть остыть.

**Если упёрлось в троттл:**
- Запускать секции по одной с паузами, а не `all`: `--report overview`, подождать, `--report sources`, ...
- Дать API остыть 10–30 мин при тяжёлом троттле.

## Базовые цифры (ориентир, 30 дней на май 2026)

Визиты ~2 700, посетители ~1 620, отказы ~31%, глубина 1.25 стр/визит. Низкая глубина — точка роста (внутренняя перелинковка, блок «похожие товары»).

## Идеи для развития скилла

- [ ] Кэширование ответов в файл (`.cache/`), как советует SEO-практика — меньше дёргать API.
- [ ] Сравнение периодов (этот месяц vs прошлый).
- [ ] Конверсии/цели (`ym:s:goal<id>reaches`) — клики по телефону, «в корзину», оформление.
- [ ] Экспорт в CSV/JSON для дальнейшей обработки.
- [ ] Интеграция Яндекс.Вебмастер API (позиции, запросы — то, что Метрика прячет).
- [ ] Day-by-day агрегация для обхода троттла на широких диапазонах.
- [ ] Поддержка нескольких счётчиков (несколько проектов у владельца токена).
